# 关卡生成约定

生成版本：`LEVEL_GENERATOR_VERSION = 6`。关卡号是唯一用户 seed，范围为 1–99999。

版本 6 修正回血概率的连续关卡相关性：`关卡号 ^ 0xA341316C` 先按 32 位无符号数执行异或右移 16、乘 `0x7FEB352D`、异或右移 15、乘 `0x846CA68B`、异或右移 16，再初始化掉落 LCG。落点序列不变。重开仍复现同一关卡，旧版掉落结果和路线须重新验证。

版本 5 在碰撞位置放下携带包裹，重叠时保留数量；快照和求解去重包含重叠数量。旧版路线和指纹须重新验证。

版本 4 按地图尺寸放置 3–5 个包裹，生成与结构检查共用 `levelPackageCount()`；求解段数上限为包裹总数的两倍。大地图的旧路线与指纹须重新验证。

版本 3 加入随机回血。掉落概率和回合使用 `关卡号 ^ 0xA341316C` 的独立 LCG 序列；落点使用 `关卡号 ^ 0xC8013EA4` 的独立序列，从掉落时按行列排列的空地中选取。不消耗叉车随机状态。待生成时，求解去重包含回合数；快照始终包含道具位置、掉落回合和状态。旧版路线与指纹须重新验证。

| 关卡号 | 行×列 | 包裹数 |
| --- | --- | --- |
| 1–999 | 9×15 | 3 |
| 1000–9999 | 9×19 | 4 |
| 10000–29999 | 11×23 | 4 |
| 30000–59999 | 13×27 | 5 |
| 60000–99999 | 17×31 | 5 |

每关有一个配送点、3–5 个包裹、四个互不重叠的叉车候选出生位置；实际使用前 N 个，N 为 1–4。机器人从配送点出发。地图使用有容量上限的二维字符数组，运行时边界为 `mapRows`、`mapCols`。

## 确定性与重试

地图生成和叉车移动分别保存随机数状态，都由同一个关卡号初始化。使用固定的 32 位无符号 LCG：`state = state * 1664525 + 1013904223`，按模 2^32 更新，不使用 C 库 `rand()` 或时间。

首次候选的生成 seed 等于关卡号。候选失败后最多重试 100 次，第 k 次重试的 seed 为：

```text
100000 + (关卡号 - 1) × 100 + (k - 1)，k = 1..100
```

重试不改变地图尺寸、对外关卡号及叉车初始随机状态。不同关卡的内部 seed 范围不重叠；不同 seed 仍可能生成相同布局，不承诺地图内容绝不重复。

同一版本、关卡号、叉车数量和操作序列应产生相同状态。R 从保存的关卡数据恢复整局及随机状态，不重新求解。修改生成、求解或移动规则可能改变旧关卡，需要更新版本和回归基线。版本 2 加入安全区、直行巡逻和限步追踪，不兼容版本 1 的叉车路线与回放指纹。

## 生成与验收

`level.c` 建立封闭外墙，添加内部障碍，再确定包裹和叉车出生位置。配送点位于 `(1,1)`；包裹和叉车出生位置的行列和至少为 7，保留起点附近空间。候选不直接进入游戏。

`validateLevel()` 检查尺寸、字符、行终止符、封闭边界、包裹和配送点数量、出生位置及重叠。从配送点做 BFS，要求所有非墙格连通。

`solver.c` 再按 1、2、3、4 辆叉车分别搜索获胜路线。搜索调用正式核心的 `takeTurn()`，包括碰撞重生、携带包裹、计分和致命碰撞优先判负。每条路线从初始状态重新执行，只有最终状态为 `GAME_WON` 才接受。候选须通过全部四种叉车配置，避免所选数量改变地图。

搜索按拾取、配送拆成最多 `2 * totalPackages` 段，用到目标的 BFS 距离引导状态搜索；每段最多保存 12000 个节点，深度上限 256，路线缓冲区上限 4096。状态包含地图、移动对象、生命、携带和配送状态、回合、暂停、叉车方向、追踪剩余回合、冷却及随机数状态。节点上限和遍历顺序固定，不使用运行时间决定接受哪个候选。

超限或没有找到路线只表示未验证，不能据此断言无解。该候选被拒绝，继续下一个内部 seed。101 个候选均失败时，终端提示重新选择关卡；SDL 在开始页显示错误，等待重新选择。下一关生成失败时保留当前关卡和结算状态。不会放行未验证地图，也不保证全部 99999 个关卡都能在上限内生成。

通过表示存在至少一条可获胜操作序列，不表示任意操作都能获胜。

## 两个前端

终端输入叉车数和关卡号，关卡直接回车默认 1；SDL 无参数启动时两个字段留空，参数 `parcel_shift.exe <关卡号> <叉车数>` 只预填字段，仍需在开始页确认。两端共用生成、检查、回合与胜负逻辑。

R 重开当前关卡；获胜后 N 进入下一关，不保留上一关得分或生命。99999 为最后一个可输入编号。SDL 使用 44×44 固定格子，画布随地图从 1280×800 扩展到最大 1808×1152；图标为 36×36。切换尺寸时调整窗口，超出屏幕工作区时等比缩小；手动缩放保持画布比例。

## 文件与检查入口

- `src/level.c/.h`：尺寸分段、随机数、候选生成、结构检查。
- `src/game.c/.h`：关卡选择、四种配置验收、正式回放、重开和状态快照。
- `src/solver.c`：有界通关路线搜索；所选配置的证据保存在 `levelSolution`。
- `tests/test_game.c`：规则、检查器反例、尺寸边界、复现及路线回放。
- `tests/test_terminal.py`：终端输入、暂停、重开、胜负、下一关及各尺寸。

基础构建后，可输出某关路线，或检查固定抽样序列：

```powershell
.\build\windows\test_game.exe --route 42 2
.\build\windows\test_game.exe --audit 250
```

抽样第 i 项为 `(i × 7919) % 99999 + 1`，叉车数量为 `i % 4 + 1`，i 从 0 开始。每行输出关卡号、尺寸、最终生成 seed、地图/出生点/路线指纹、获胜回合和剩余生命；每次初始化内部均检查全部四种叉车数量。
